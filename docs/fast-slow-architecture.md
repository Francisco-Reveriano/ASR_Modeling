# Fast and Slow Translation Architecture

## Implemented local foundation

This repository implements a usable local workflow, not the complete production TRS.

`app.py` connects microphone/WAV input to Silero VAD and the selected transcriber. Both inputs default to `gpt-live-transcribe + gpt-6-luna`, with `Breeze + OpenAI` available in independent dropdowns. The model pair is frozen on start and retained with results. Evaluation keeps its local Breeze baseline. Completed speech segments feed independent OpenAI and local Tencent translation queues. Fast OpenAI drafts also enter the Astra correction worker, followed by a sequential conversation review. Four numbered model columns preserve source order; the optional reference pane keeps its own file-line numbering. Microphone settings select Fast English, Corrected English, Fully reviewed English, or Compare all translations. The selected mode is frozen on Start, controls worker creation as well as visible columns, and does not change the upload/evaluation comparison workflow. Modes without Tencent avoid its loading/inference for that recording.

`src/openai_transcription.py` sends speech audio to OpenAI's Realtime transcription endpoint as 24 kHz PCM16. Each utterance owns one connection and committed item, with a bounded response wait and safe errors. Only matching completed transcripts enter translation; partial deltas are not published. Uploads use the same adapter. No local model lock covers cloud requests. Breeze keeps audio local, and evaluation references never enter either transcriber or translation prompts.

The additional `gpt-realtime-translate` choice uses `src/realtime_translation.py` for continuous audio-to-English captions. A session-owned worker sends and receives concurrently through `/v1/realtime/translations`, with output language fixed to `en` and optional source captions from `gpt-realtime-whisper`. Microphone capture queues audio without network I/O; uploads stream bounded frames at playback speed. Neither path cuts out silence or calls text translators, Astra, glossary processing, or diarization. Captions are two independent growing texts, without fabricated segment alignment. Stop drains through `session.closed`; failures and user-cancelled uploads retain explicitly incomplete captions. Cancellation suppresses late deltas, clears queued audio, and closes the connection. Tests cover English routing, partial publication, completion, cancellation, overflow, safe errors and buffer release.

`src/pipeline.py` resamples to mono 16 kHz, processes 512-sample/32 ms VAD frames, and queues speech without waiting for ASR. Silence is fixed at 500 ms; continuous speech is capped at 15 seconds. Breeze and Tencent share a local model lock. This is utterance transcription, not streaming ASR partials.

`src/diarization.py` independently streams continuous audio through local CPU Nemotron weights. Its rolling windows and speaker cache survive VAD boundaries. Time overlap attaches anonymous speaker labels to ASR segments; translation never waits for them. The audio backlog is bounded, with an explicit failure on overflow. See the [NVIDIA model card](https://huggingface.co/nvidia/Nemotron-3-Diarization/blob/main/README.md); advertised model latency is not measured application latency.

## Session ownership and correction policy

Starting a recording/file closes previous workers and freezes `SlowLaneConfig`, including the correction model, reasoning effort, and initial response cap loaded from `.env`. Every review has one editable segment. Defaults are ten earlier context segments, up to two already available following source segments, a conservative 2,000 UTF-8-byte source budget, 16,384 tokens shared by reasoning and the translation response, and confidence threshold 0.6. Nearby evidence uses the source budget remaining after the editable segment; an individually valid long segment still dispatches when a neighbor cannot fit. Context stays chronological and read-only, excludes the editable/filtered rows, and distinguishes reviewed, provisional, and unavailable English. Following source text can be useful before its fast translation finishes. No request waits for future speech. There are no request timeouts, revision horizons, seal deadlines, or age-based eligibility windows. Pause and glossary reload are explicit runtime actions.

Each session and segment receives an immutable ID. Every completed fast draft independently starts a single-segment review; multiple requests run concurrently. A process-wide limit of 64 active API calls includes canceled calls that have not finished. When all slots are occupied, ready rows stay in the transcript until a slot opens, without a waiting thread or copied request per row. Version checks reject stale writes, and validation applies each complete response atomically to its row. Results may finish out of order and are published immediately while transcript display/export order stays unchanged. A slow or failed request does not hold back another completed correction. A response must review its requested segment exactly once; omitted or oversized segments produce explicit retryable failures. Errors preserve English drafts. An explicit fast failure schedules an Astra attempt using the original source; failures remaining after bounded recovery require manual retry. Source fallbacks remain flagged in raw audit history but are never presented or exported as English: the English column and TXT/CSV/SRT/VTT fields show Translation unavailable until a valid English result exists.

The app seeds source rows and available timing/speaker metadata before starting fast translation. The OpenAI session notifies its captured correction session after each completed outcome, outside the translation lock and without accessing Streamlit state. Prefix-safe submissions tolerate a delayed notification when the UI already knows more rows; notifications from an old conversation remain bound to its closed session. UI polling refreshes metadata and provides recovery if an observer fails, but review dispatch does not depend on a browser refresh. Tencent remains independent.

An accepted correction always publishes the reviewed text to both live and final views with a Corrected badge and subtle green cell tint; accepted `no_change` also synchronizes the displayed text and shows Confirmed. Within each pass, the first accepted correction, `no_change`, explicit pause, or close seals available text. Waiting never seals a result. Each pass's sealed text stays immutable; the combined display may advance from the first accepted pass to the newer second-pass result. Responses to sealed, paused, or closed passes remain rejected. Explicit cancellation stops waiting without requiring a deadline; abandoned request threads stay bounded. This supersedes the earlier TRS screen-freezing and timed-sealing policy.

`src/conversation_review.py` composes the asynchronous first correction session with a sequential conversation-review session. The second pass starts a row only after its first review and all preceding eligible second reviews have succeeded. It uses the newest second-reviewed earlier English and available first-reviewed following context, with the original source still controlling what is supportable. No request waits for speech that has not arrived or for recording to stop. Both passes share the same frozen correction model, token budget, validation, and process-wide active-call limit. The optional `conversation_reasoning_effort` preserves deeper background review when live speech uses Low reasoning for the first pass; absent that override, both passes use the configured effort. Each accepted response publishes immediately; first-pass reviews still complete independently while the second pass advances in source order.

Optional TTS freezes an Astra speech mode per conversation. **Live corrections** selects the immutable accepted text from `first_pass`, so sequential review never delays voice and later wording changes never alter or replay queued audio. With the exact `gpt-6-astra` model it uses Low reasoning for the first pass and retains the configured effort for conversation review. Custom models retain their configured effort. **Full review** waits for the newest accepted conversation review when that pass is enabled. Drafts, paused fallbacks, failed reviews, source-script output, and filtered rows are never spoken. Neither mode alters correction reasoning when speech is disabled. Exports retain the speech mode and each pass's actual reasoning configuration.

The voice player mounts in a stable slot before recording/file start, resumes Web Audio on trusted app gestures, and attempts autoplay. A visible Enable sound fallback covers browser/embedding restrictions. Each speech session has a 60-second initial lead-in measured with server monotonic time, beginning when its first accepted English passage enters the TTS queue. Before that, `playback_delay_ms` is null and the browser waits for translation. The first non-null remaining delay establishes the browser deadline; later polls do not restart it. Audio can start when the minute expires without another server render. Reconnecting uses the remaining server delay. At startup and after an underrun it targets two seconds of ready audio, waiting at most two seconds once any audio arrives. A separate `generation_complete` flag flushes short final clips without waiting for playback acknowledgements. Pause and Stop override automatic start. Two bounded TTS producers prefetch English passages while a single publisher preserves audio order. Published PCM stays bounded at 60 seconds, plus at most two seconds of prefetch and two seconds of near-silence lookbehind per producer. The browser schedules contiguous chunks on one clock with four seconds of lookahead; a chunk arriving before the previous one ends does not receive an extra startup cushion.

The TTS dropdown selects `gpt-4o-mini-tts` (default) or `tts-1-hd`, frozen per conversation. HD requests omit unsupported delivery instructions; both use streaming PCM and the same preset speaker voices. Already available sentences within one row are grouped into passages up to 300 characters, preserving speaker boundaries. `src/speech_audio.py` examines 10 ms PCM frames and shortens only near-silent request edges (-54 dBFS peak), retaining 80 ms leading and 120 ms trailing padding. Internal pauses and all audible frames are preserved; a bounded two-second lookbehind streams excess quiet audio through. The audio samples are not sped up or overlapped.

Speech uses stable preset voices for the eight anonymous Nemotron channels. Speaker metadata is captured when each accepted text row enters the speech queue. Mixed labels use the dominant overlapping channel; unknown/late labels and standalone realtime translation use the default voice. There is no word-level attribution, voice cloning, or replay after late speaker/correction updates. Local diarization can lag translation, so a distinct voice for every actual speaker is not guaranteed. Disabling Different voice per speaker selects the default voice for the session.

First-pass failure blocks the second pass at that row. Second-pass failure leaves the last accepted English visible and blocks subsequent second reviews until retry; it does not undo accepted first corrections. Filtered and explicitly paused rows are skipped without being marked reviewed. The combined snapshot carries stage-specific progress/status and the latest accepted text, while separate first- and second-pass snapshots retain their audit history. A new conversation closes both stages so late results cannot change the active conversation.

State, histories, and ordered events remain in memory. Downloads provide conversation TXT, session JSON, sealed bilingual CSV, and SRT/VTT using measured segment offsets. These exports do not provide durable recovery.

Audio is retained only while needed for processing. Live ASR releases each completed speech buffer and clears residual capture buffers after its queue drains or fails. Upload jobs retain decoded audio and segment views across reruns, then release them on completion or failure; the speaker worker owns its separate copy. The selected WAV remains available for playback and retry through Streamlit's uploader. No decoded-audio archive is kept with the conversation results.

## API, terminology, and reference boundaries

Fast translation uses `gpt-6-luna` for the default pair, with the previous two segments, up to 40 local glossary hits, and exact identifier checks. For Breeze and evaluation, `OPENAI_DEFAULT_MODEL` selects its model. `OPENAI_DEFAULT_REASONING_EFFORT` explicitly selects fast reasoning effort independently of correction settings. Missing/blank effort preserves `none` for `gpt-6-luna` and the provider's default for other models. Completed utterances use a 512-token output cap rather than the TRS 64-token streaming clauses.

All translation prompts require English and romanized names. A shared script guard rejects untranslated Han, kana, Bopomofo, and Hangul while allowing accented Latin names and technical identifiers; it is not a general language classifier. Completed mixed-script OpenAI output gets one repair request from the same original input and settings, capped at 512 output tokens. Fast-provider API errors receive no automatic retry. Astra validation also rejects mixed-script corrections and `no_change` confirmations of raw source fallbacks. Presentation guards cover older snapshots as well as new provider results.

Fast output also gets that single bounded repair when exact protected identifiers change. `OPENAI_FILTER_BACKGROUND_SPEECH` defaults to true: prompts retain uncertain speech and legitimate topic changes while omitting clearly separate background chatter. Only successful main-conversation rows supply the two preceding context items. Explicit fully filtered results have their own state, are sealed without an Astra request, and remain in transcript/audit exports but not captions. Astra receives the frozen filtering setting so reviews of mixed segments preserve intentional background omissions. Filtering uses transcript text and does not perform audio source separation.

Completed Tencent output containing source-script words receives one deterministic local English repair from the same original transcript. Both attempts remain under `LOCAL_MODEL_LOCK`; incomplete, empty, or repeatedly non-English results remain failures. No local repair calls OpenAI or downloads model assets.

Astra's contextual review treats ASR and fast drafts as noisy evidence. It actively repairs supported homophones, mangled code-switching, technical mistranslations, clause boundaries, and referents to produce coherent English. Nearby source, repeated terminology, grammar, and phonetic plausibility must support repairs; a domain story or earlier model guess alone is insufficient. Actual identifiers, quantities, negation, and uncertainty stay intact. `[unclear]` is reserved for the smallest unrecoverable detail, rather than replacing recoverable clauses or a good draft. The configured confidence floor still applies without inflation. After a schema, confidence, English, identifier, or version validation failure, or an incomplete response with the exact `max_output_tokens` reason, each affected current segment gets one fresh singleton review with an allowlisted failure category. These failures share one automatic retry allowance per row. Retries preserve the frozen token cap and original source/draft; truncated partial output is never accepted. Every response still passes the same atomic validation. Other provider failures do not trigger automatic recovery. Persistent failures retain drafts, expose a safe category, and require manual retry. Provider failures expose only fixed error categories, allowlisted incomplete reasons, and numeric HTTP status; raw exception bodies and credentials never enter session diagnostics.

The slow adapter defaults to [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra) with `reasoning.effort="medium"`, configurable through `OPENAI_CORRECTION_MODEL` and `OPENAI_CORRECTION_REASONING_EFFORT`. `OPENAI_CORRECTION_MAX_OUTPUT_TOKENS` supplies the initial combined reasoning/response cap (default 16,384; accepted range 512–16,384), which the next-session Streamlit control can override. Smaller configured caps remain exact; high reasoning can consume that budget before producing complete structured output. It uses the [Responses API](https://developers.openai.com/api/docs/guides/text) and a [strict JSON schema](https://developers.openai.com/api/docs/guides/structured-outputs). Existing environment variables take precedence over `.env`, and requests use the session's frozen settings. Astra explicitly sets SDK `timeout=None`, disables SDK retries, and disables response storage. Provider or connection failures still surface as retryable errors. Allowlisted text/context/terminology fields exclude audio, evaluation references, and unrelated metadata. Cloud text transmission means this is not an on-premises/no-egress deployment.

`src/glossary.py` loads explicit CSV/TSV/JSON/XLSX terminology and optional TXT DNT lists. Reload swaps a complete validated snapshot. CJK DNT terms and aliases fail validation because exact preservation conflicts with English output; Chinese-to-English glossary mappings remain valid. Accepted evidence from two distinct segments promotes a compatible term pair for later translation; the master remains unchanged. The requested 6,011-entry glossary was not supplied. Reference uploads remain evaluation/display inputs, never terminology or model context; English translations have no numerical quality score.

## TRS coverage and remaining gates

| Requirement group | Current coverage and gaps |
| --- | --- |
| FR-IN, FR-ASR, FR-STB | Capture, preprocessing, bounded segments, segment offsets. Missing synchronized client clock, full raw-session retention, configurable 300–800 ms VAD, low-energy live splitting, 500 ms ASR partials, 500 hotwords, word timestamps/confidence, LA2 and clause stabilization. |
| FR-FT, CTX, RL | Independent workers, concurrent single-segment reviews, contextual drafts, bounded windows, schema/confidence/DNT validation, `no_change`. Missing token streaming, 50 ms dispatch guarantee, GraphRAG and audio re-decode. |
| COR, STO, UI | IDs, versions, atomic corrections, first sealing, separate live/final views, audit/export, status badges. Missing durable persistence and reconnect transport; live UI polls every 500 ms, with 100 ms updates while waiting for WAV ASR, not a 50 ms event guarantee. |
| GL, SES, LANG | Local terminology/reload/learning and recorded session configuration. Missing ASR terminology refresh, server affinity/prefix-warming guarantees, four-hour compaction, and validated config-only language-pair portability. |
| NFR-L/Q/C/A/S/O, DEP | Production latency, quality, capacity, recovery, security, observability and deployment gates remain unvalidated or unimplemented. No dedicated GPU pools, TLS/RBAC layer, retention service, distributed tracing or production shadow rollout. |

Mocked tests verify state transitions, payload boundaries, safe rendering and failure behavior. They do not establish p95 fast ≤2 s/slow ≤15 s, interference <5%, ASR/terminology/COMET/human-quality targets, four/twenty concurrent sessions, or four-hour soak performance. Those require representative audio, supplied terminology, deployment hardware and measured acceptance runs.
